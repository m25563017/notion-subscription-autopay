# Notion 訂閱自動補帳 + 每月狀況報告 Email

管理 Notion 上的訂閱清單時，兩件事很容易忘記：把每期的繳費紀錄補進去、以及定期檢查有沒有「說要退訂卻一直沒退」的訂閱。這個專案用兩個排程腳本處理掉這兩件事。

- **自動補帳（每天）**：掃過「訂閱產品」，對每一筆已經到期、卻還沒有對應「繳費紀錄」的訂閱補上紀錄，並依 Notion 端算出的「下次繳費時間」一路追平到今天。
- **每月狀況報告（每月 10 號）**：用 Resend 寄一封 Email，分區列出正常計費中、暫停中、以及標記為準備取消的訂閱，並估算目前每月總花費。

## 運作邏輯

| 腳本         | 指令                    | Workflow                             | 排程（台北時間） |
| ------------ | ----------------------- | ------------------------------------ | ---------------- |
| 自動補帳     | `npm run catchup`       | `.github/workflows/DailyCatchup.yml` | 每天 09:00       |
| 每月狀況報告 | `npm run monthly-email` | `.github/workflows/MonthlyEmail.yml` | 每月 10 號 09:00 |

**自動補帳**只處理同時滿足這些條件的訂閱：`自動續訂` 打勾、`暫停訂閱` 未打勾、`準備取消` 未打勾、`訂閱類型` 。對每一筆到期訂閱，先用「產品 + 繳費日期」判斷是否已有紀錄以免重複，補一筆後等 Notion 的公式/彙總欄位更新出新的「下次繳費時間」，再繼續下一期；單筆最多追平 60 期。

**每月花費**的估算：`訂閱類型` 為「年」的算 `價格 ÷ 12`，「月」的算 `價格`，暫停中或其他類型不計入。

## Notion 資料庫結構

需要兩個資料庫，欄位名稱對應在 `src/notion.js` 的 `SUB_PROPS` / `PAY_PROPS`，要改名只需動這兩個物件。

### 訂閱產品

腳本會讀取的欄位：

| 欄位         | 型別         | 用途                                               |
| ------------ | ------------ | -------------------------------------------------- |
| 名稱         | 標題         | 訂閱名稱                                           |
| 訂閱類型     | 選項         | `月` / `年` / `終`（終身，不自動補帳、不計入月費） |
| 價格         | 數字         | 每期金額，補帳時寫進繳費紀錄、也是月費估算基礎     |
| 下次繳費時間 | 公式（日期） | 由繳費紀錄推算的下一期日期，補帳的追平依據         |
| 自動續訂     | 核取方塊     | 只有打勾才會被自動補帳                             |
| 暫停訂閱     | 核取方塊     | 打勾則跳過補帳、月費以 0 計                        |
| 準備取消     | 核取方塊     | 打勾則跳過補帳，並在每月報告中獨立列出             |

其餘欄位（產品類型、繳費提醒、每月花費、贈送時長、累計金額等公式/彙總欄位，以及「繳費」按鈕）供 Notion 內檢視用，腳本不依賴。

### 繳費紀錄

| 欄位     | 型別               | 用途                              |
| -------- | ------------------ | --------------------------------- |
| 名稱     | 標題               | 補帳時寫入「訂閱名稱 + 繳費日期」 |
| 產品     | 關聯（→ 訂閱產品） | 對應的訂閱                        |
| 繳費日期 | 日期               | 該期繳費日                        |
| 繳費金額 | 數字               | 該期金額                          |

## 設定

1. 到 <https://www.notion.so/my-integrations> 建立 internal integration，並在兩個資料庫的 `連結` 選單把它加進去。
2. 環境變數如下：

| 變數                    | 說明                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `NOTION_TOKEN`          | integration token                                                                                                  |
| `NOTION_SUBS_DB_ID`     | 「訂閱產品」Database ID                                                                                            |
| `NOTION_PAYMENTS_DB_ID` | 「繳費紀錄」Database ID                                                                                            |
| `RESEND_API_KEY`        | Resend API Key                                                                                                     |
| `MAIL_TO`               | 收每月報告的信箱                                                                                                   |
| `MAIL_FROM`             | 選填。留空會用 Resend 的 `onboarding@resend.dev`（只能寄給你註冊 Resend 的信箱）；驗證網域後可改成自己網域下的地址 |

Database ID 是資料庫完整頁面網址中那段 32 碼英數字。

3. 本地測試：

```bash
npm install
npm run catchup
npm run monthly-email
```

兩個 workflow 的 cron 已設定好（以 UTC 撰寫，換算為台北時間 09:00），可先在 GitHub `Actions` 頁手動 `Run workflow` 各跑一次確認。
